# 🚀 Запуск Mistral 7B: от простого к сложному

Полное руководство по запуску языковой модели Mistral 7B двумя способами: через удобный Ollama (для новичков) и через продвинутый llama.cpp (для тонкой настройки).

---

## 📋 Системные требования

- **Docker Desktop** (с поддержкой Linux-контейнеров)
- **Visual Studio Code** (или любой терминал)
- **Windows 10/11** (инструкция адаптирована под PowerShell)
- **Минимум 8 ГБ ОЗУ** (рекомендуется 16+ ГБ)
- **~4 ГБ свободного места на диске** (под модель)

---

## 🛠️ Шаг 0: Установка инструментов

Установите необходимые приложения, если они ещё не установлены:

- [**Docker Desktop**](https://www.docker.com/products/docker-desktop/) — платформа для контейнеризации
- [**VS Code**](https://code.visualstudio.com/) — редактор кода со встроенным терминалом

> **Важно:** После установки Docker Desktop убедитесь, что он запущен и работает в фоновом режиме (значок в системном трее).

---

# 🟢 Часть 1: Лёгкий старт с Ollama

*Самый простой способ. Ничего скачивать и настраивать не нужно — одна команда, и вы в чате с Mistral.*

---

## 📥 Шаг 1.1: Запуск контейнера Ollama

Откройте терминал в VS Code (`Terminal → New Terminal`) и выполните:

```powershell
docker run -d -v ollama:/root/.ollama -p 11434:11434 --name ollama ollama/ollama
```

### 🔍 Что значат флаги:
| Флаг | Назначение |
|------|-----------|
| `-d` | Запуск в фоновом режиме |
| `-v ollama:/root/.ollama` | Сохранение моделей между перезапусками |
| `-p 11434:11434` | Порт для API (если не нужен API, можно убрать) |
| `--name ollama` | Имя контейнера |

### 🎛️ Опционально: ограничение ядер CPU

Если компьютер тормозит при работе модели:

```powershell
# Сначала удалите существующий контейнер
docker rm -f ollama

# Запустите с ограничением (например, 4 ядра)
docker run -d --cpus="4" -v ollama:/root/.ollama -p 11434:11434 --name ollama ollama/ollama
```

---

## 💬 Шаг 1.2: Запуск модели и чат

```powershell
docker exec -it ollama ollama run mistral
```

> При первом запуске модель **скачается автоматически** (~4 ГБ). Подождите пару минут. В следующий раз запустится мгновенно.

После загрузки вы попадёте в интерактивный чат:

```
>>> Привет! Как дела?
```

Просто печатайте сообщения — модель будет отвечать.

**Выйти из чата:** `/bye` или `Ctrl+D`

---

## 🛑 Шаг 1.3: Остановка контейнера

Когда закончили работу — освободите ресурсы:

```powershell
docker rm -f ollama
```

# 🔴 Часть 2: Продвинутая настройка с llama.cpp

*Для тех, кто хочет полный контроль: API, потоковая генерация, точная настройка параметров — всё через скрипты.*

---

## 📥 Шаг 2.1: Клонирование репозитория

```bash
git clone https://github.com/malikkhubiev/llama.cpp-mistral.7b.git
cd llama.cpp-mistral.7b
```

> Репозиторий содержит скрипты и конфигурационные файлы.

---

## 🐳 Шаг 2.2: Запуск Docker-контейнера с моделью

В терминале VS Code (находясь в директории проекта) выполните:

```powershell
docker run -d `
  --name llama-mistral `
  --cpus="11" `
  -p 8080:8080 `
  -v ${PWD}\models:/models `
  yusiwen/llama.cpp:latest `
  /llama.cpp/llama-server `
  -m /models/mistral-7b-q4.gguf `
  --host 0.0.0.0 `
  --port 8080 `
  --threads 11 `
  --threads-batch 16 `
  --ctx-size 4096 `
  --batch-size 512 `
  -np 1 `
  --mlock `
  --no-mmap
```

### 🔍 Разбор параметров:
| Параметр | Назначение |
|----------|-----------|
| `-d` | Запуск в фоновом режиме |
| `--cpus="11"` | Ограничение использования CPU |
| `-p 8080:8080` | Проброс порта для API |
| `-v ${PWD}\models:/models` | Монтирование папки с моделью |
| `--threads 11` | Потоки для обработки запросов |
| `--ctx-size 4096` | Размер контекстного окна в токенах |
| `--batch-size 512` | Размер пакета при обработке |
| `-np 1` | Количество параллельных слотов |
| `--mlock` | Блокировка модели в ОЗУ |
| `--no-mmap` | Отключение memory-mapping (полезно для Windows) |

> **Примечание:** При первом запуске Docker автоматически загрузит образ `yusiwen/llama.cpp:latest` (~1 ГБ).

---

## ⚙️ Шаг 2.3: Настройка параметров генерации

Откройте файл `rules.json` в VS Code и настройте параметры под ваши задачи:

```json
{
  "container": {
    "cpus": 11,
    "threads": 11,
    "threads_batch": 16,
    "ctx_size": 4096,
    "batch_size": 512
  },
  "llm": {
    "prompt": "Ваш запрос к модели...",
    "temperature": 0.7,
    "top_p": 0.9,
    "top_k": 40,
    "repeat_penalty": 1.1,
    "presence_penalty": 0.0,
    "frequency_penalty": 0.0,
    "max_tokens": 300,
    "n": 1
  }
}
```

### 📊 Описание параметров LLM:

| Параметр | Диапазон | Описание |
|----------|----------|----------|
| `prompt` | текст | Инструкция для модели |
| `temperature` | 0.0 – 2.0 | "Креативность": 0 = строго, 2 = творчески |
| `top_p` | 0.0 – 1.0 | Nucleus sampling: порог вероятности |
| `top_k` | 1 – N | Топ-K самых вероятных токенов |
| `repeat_penalty` | 1.0 – 2.0 | Штраф за повторы (>1 = меньше повторов) |
| `presence_penalty` | -2.0 – 2.0 | Поощрение/штраф новых тем |
| `frequency_penalty` | -2.0 – 2.0 | Штраф за частые слова |
| `max_tokens` | 1 – 4096 | Максимальная длина ответа |
| `n` | 1 – N | Сколько вариантов ответа сгенерировать |

---

## 🎯 Шаг 2.4: Отправка запроса к модели

Запустите скрипт потоковой генерации:

```powershell
.\streaming.ps1
```

### 🔄 Как работает скрипт:

1. **Читает** `rules.json` и извлекает параметры
2. **Вычисляет хеш** конфигурации контейнера для отслеживания изменений
3. **Проверяет**, запущен ли контейнер `llama-mistral`:
   - Если конфигурация изменилась — пересоздаёт контейнер
   - Если контейнер не запущен — запускает с актуальными параметрами
4. **Ожидает готовности** сервера (до 120 секунд с индикацией: `| / - \`)
5. **Отправляет API-запрос** с параметрами из `rules.json`
6. **Обрабатывает потоковый ответ** в реальном времени (SSE)
7. **Сохраняет результат** в `replies.txt`

---

## 📖 Шаг 2.5: Просмотр результатов

- **В терминале:** токены появляются по мере генерации
- **В файле `replies.txt`:** полный ответ сохраняется после завершения

## 🔧 Устранение неполадок

| Проблема | Решение |
|----------|---------|
| **"port already in use"** | Порт занят. Измените порт в команде запуска |
| **Docker не запускается** | Проверьте, что Docker Desktop активен в трее |
| **Высокое потребление памяти** | Уменьшите `ctx_size` в `rules.json` |
| **Медленная генерация** | Увеличьте `threads` в `rules.json` |
| **Ошибка PowerShell** | `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` |

## ⚡ Сравнение: Ollama vs llama.cpp

| Критерий | 🟢 Ollama | 🔴 llama.cpp |
|----------|----------|-------------|
| **Сложность** | Минимальная | Высокая |

| **API** | Есть (базовый) | Полноценный REST API |
| **Потоковая генерация** | Нет | Да |
| **Параметры генерации** | Стандартные | Все регулируются |
| **Управление ресурсами** | Базовое | Детальное |
| **Для кого** | Новички, быстрое знакомство | Разработчики, продакшен |
