# 🚀 Запуск Mistral 7B с глубокой настройкой через llama.cpp

Пошаговое руководство по развертыванию и тонкой настройке большой языковой модели Mistral 7B в Docker-контейнере с использованием llama.cpp и кастомного API-клиента.

## 📋 Системные требования

- **Docker Desktop** (с поддержкой Linux-контейнеров)
- **Visual Studio Code**
- **Windows 10/11** (инструкция адаптирована под PowerShell)
- **Минимум 8 ГБ ОЗУ** (рекомендуется 16+ ГБ для комфортной работы)
- **~4 ГБ свободного места на диске** (под модель)

---

## 🛠️ Шаг 1: Установка инструментов

Установите необходимые приложения, если они ещё не установлены:

- [**Docker Desktop**](https://www.docker.com/products/docker-desktop/) — платформа для контейнеризации
- [**VS Code**](https://code.visualstudio.com/) — редактор кода со встроенным терминалом

```bash
git clone https://github.com/malikkhubiev/llama.cpp-mistral.7b.git
cd llama.cpp-mistral.7b
```

> Репозиторий содержит скрипты и конфигурационные файлы для работы с Mistral.

---

## 🐳 Шаг 3: Запуск Docker-контейнера с моделью

В терминале VS Code (находясь в директории проекта) выполните команду:

```powershell
docker run -d `
  --name llama-mistral `
  --cpus="11" `
  -p 8080:8080 `
  -v ${PWD}\models:/models `
  yusiwen/llama.cpp:latest `
  /llama.cpp/llama-server `
  -m /models/mistral-7b-q4.gguf `
  --host 0.0.0.0 `
  --port 8080 `
  --threads 11 `
  --threads-batch 16 `
  --ctx-size 4096 `
  --batch-size 512 `
  -np 1 `
  --mlock `
  --no-mmap
```

### 🔍 Разбор параметров:
| Параметр | Назначение |
|----------|-----------|
| `-d` | Запуск в фоновом режиме |
| `--cpus="11"` | Ограничение использования CPU |
| `-p 8080:8080` | Проброс порта для API |
| `-v ${PWD}\models:/models` | Монтирование папки с моделью |
| `--threads 11` | Потоки для обработки запросов |
| `--ctx-size 4096` | Размер контекстного окна |
| `--mlock` | Блокировка модели в ОЗУ |
| `--no-mmap` | Отключение memory-mapping (полезно для Windows) |

> **Примечание:** При первом запуске Docker автоматически загрузит образ `yusiwen/llama.cpp:latest` (~1 ГБ).

## ⚙️ Шаг 4: Настройка параметров генерации

Откройте файл `rules.json` в VS Code и настройте параметры под ваши задачи:

```json
{
  "container": {
    "cpus": 11,
    "threads": 11,
    "threads_batch": 16,
    "ctx_size": 4096,
    "batch_size": 512
  },
  "llm": {
    "prompt": "Write a practical to-do list of what I have to do to become extremely popular in TikTok",
    "temperature": 2.0,
    "top_p": 0.9,
    "top_k": 40,
    "repeat_penalty": 1.1,
    "presence_penalty": 0.3,
    "frequency_penalty": 0.5,
    "max_tokens": 300,
    "n": 1
  }
}
```

### 📊 Описание параметров LLM:

| Параметр | Диапазон | Описание |
|----------|----------|----------|
| `prompt` | текст | Инструкция для модели |
| `temperature` | 0.0 – 2.0 | "Креативность" ответов (0 = детерминированно, 2 = максимально разнообразно) |
| `top_p` | 0.0 – 1.0 | Nucleus sampling: порог вероятности для отбора токенов |
| `top_k` | 1 – N | Ограничение выбора K наиболее вероятными токенами |
| `repeat_penalty` | 1.0 – 2.0 | Штраф за повторение токенов (>1 снижает повторы) |
| `presence_penalty` | -2.0 – 2.0 | Штраф/награда за появление новых токенов |
| `frequency_penalty` | -2.0 – 2.0 | Пропорциональный штраф частоте токенов |
| `max_tokens` | 1 – 4096 | Максимальная длина генерируемого ответа |
| `n` | 1 – N | Количество генерируемых вариантов ответа |

### 📊 Описание параметров контейнера:

| Параметр | Описание |
|----------|----------|
| `cpus` | Количество CPU, выделяемых контейнеру |
| `threads` | Количество потоков для обработки одного запроса |
| `threads_batch` | Количество потоков для пакетной обработки |
| `ctx_size` | Размер контекстного окна в токенах |
| `batch_size` | Размер пакета при обработке |

## 🎯 Шаг 5: Отправка запроса к модели

Запустите скрипт потоковой генерации в терминале VS Code:

```powershell
.\streaming.ps1
```

### 🔄 Как работает скрипт:

1. **Читает** `rules.json` и извлекает параметры LLM и контейнера
2. **Вычисляет хеш** конфигурации контейнера для отслеживания изменений
3. **Проверяет**, запущен ли контейнер `llama-mistral`:
   - Если конфигурация изменилась — пересоздаёт контейнер
   - Если контейнер не запущен — запускает с актуальными параметрами
4. **Ожидает готовности** сервера (до 120 секунд с индикацией прогресса)
5. **Отправляет API-запрос** с параметрами из `rules.json` (все параметры LLM, кроме `prompt`, передаются как есть)
6. **Обрабатывает потоковый ответ** в формате SSE (Server-Sent Events)
7. **Сохраняет результат** в `replies.txt`

> Скрипт читает параметры из `rules.json`, отправляет API-запрос к контейнеру и обрабатывает потоковый ответ.

## 🛑 Шаг 7: Остановка и очистка

**Обязательно завершите работу контейнера**, чтобы освободить системные ресурсы:

```powershell
docker rm -f llama-mistral
```

Эта команда:
- Останавливает контейнер (если запущен)
- Удаляет контейнер и освобождает занятую память

> **Рекомендация:** Выполняйте эту команду после каждого сеанса работы с моделью.

## 🔧 Устранение неполадок

| Проблема | Решение |
|----------|---------|
| **Ошибка "port already in use"** | Порт 8080 занят. Измените `-p 8080:8080` на другой (например, `8081:8080`) |
| **Docker не запускается** | Проверьте, что Docker Desktop активен в системном трее |
| **Высокое потребление памяти** | Уменьшите `ctx_size` до 2048 или 1024 в `rules.json` |
| **Медленная генерация** | Увеличьте `threads` до значения вашего CPU-1 в `rules.json` |
| **Ошибка в PowerShell скриптах** | Проверьте политику выполнения: `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` |
| **Контейнер не пересоздаётся при изменении настроек** | Проверьте файл `.container-hash` — удалите его вручную, если нужно принудительно пересоздать контейнер |
